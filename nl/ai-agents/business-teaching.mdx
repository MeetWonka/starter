Als je je zakelijke context aan agenten meegeeft, begrijpen ze de terminologie, processen en het beleid van je bedrijf. Zo geven ze antwoorden die aansluiten bij jouw werkelijke activiteiten in plaats van generieke aannames.

<Info>
Zakelijke context helpt een agent om jouw exacte terminologie te gebruiken, jouw processen te volgen en zich aan het beleid van je bedrijf te houden.
</Info>

---

## Waarom zakelijke context meegeven?

Zonder zakelijke context doet een agent generieke aannames. Mét context geeft hij nauwkeurige, bedrijfsspecifieke antwoorden.

**Voorbeeld — een klantenservice-e-mail schrijven:**

**Zonder context:** "De meeste bedrijven bieden terugbetaling binnen 14 tot 30 dagen. Controleer het beleid van je bedrijf."

**Met context:** "Ons terugbetalingsbeleid staat een aanvraag toe binnen 30 dagen, verwerkt binnen 3-5 werkdagen. Zal ik er een starten?"

## Hoe geef je zakelijke context mee?

### Voeg context toe in de sectie Gedrag

Voeg bedrijfsspecifieke informatie rechtstreeks toe aan de instructies van de agent, in de sectie **Gedrag**. Begin met de essentie en breid uit waar nodig.

<AccordionGroup>
<Accordion title="Toon en stijl" icon="message">
Bepaal hoe de agent moet communiceren, passend bij je merk.

**Voorbeeld:**
```
Communicatiestijl:
- Professioneel maar vriendelijk, nooit te informeel
- Actieve stem en directe taal
- Klanten aanspreken met voornaam
- Beknopte, bruikbare antwoorden
```

<Tip>
Geef specifieke zinnen op die gebruikt of vermeden moeten worden. Dit zorgt voor consistentie over alle interacties van de agent.
</Tip>
</Accordion>

<Accordion title="Terminologie en woordenlijst" icon="book">
Definieer bedrijfsspecifieke termen, productnamen en afkortingen.

**Voorbeeld:**
```
Belangrijke termen:
- "Premium-niveau" = enterprise-abonnementsniveau
- "Quick-start" = ons onboardingtraject van 15 minuten
- MRR = maandelijkse terugkerende omzet
- CS = Customer Success (niet Customer Support)
```

Duidelijke definities voorkomen misverstanden en zorgen dat de agent jouw taal gebruikt.
</Accordion>

<Accordion title="Beleid integreren" icon="shield">
Voeg relevant beleid toe zodat de agent vragen nauwkeurig kan beantwoorden.

**Voorbeeld:**
```
Belangrijk beleid:
- Terugbetalingen: volledig binnen 30 dagen, verwerkt in 3-5 werkdagen
- Openingsuren support: 9-18u, maandag-vrijdag
- Reactie-SLA: 4 werkuren standaard, 1 uur voor enterprise
- Escalatie: aanvragen boven 500 € vereisen goedkeuring van een manager
```

<Warning>
Controleer altijd of de agent het beleid correct toepast voordat je hem met je team deelt. Test met realistische scenario's.
</Warning>
</Accordion>

<Accordion title="Procesinstructies" icon="list-check">
Documenteer stapsgewijze workflows die de agent moet volgen.

**Voorbeeld:**
```
Onboardingproces klant:
1. Verstuur welkomstmail met inloggegevens
2. Plan een kennismakingsgesprek binnen 48 uur
3. Wijs een dedicated success manager toe
4. Geef toegang tot trainingsmateriaal
5. Volg op na 7 dagen
```

Duidelijke processen zorgen voor consistentie en volledigheid in de acties van de agent.
</Accordion>
</AccordionGroup>

**Beste praktijk:** werk de instructies bij wanneer beleid of processen wijzigen. Verouderde context leidt tot onjuiste informatie.

### Documenten uploaden voor diepere context

Voor uitgebreide informatie zoals productdocumentatie, beleidshandboeken of kennisbanken upload je documenten in de sectie **Kennis**, zodat de agent ze automatisch kan doorzoeken en raadplegen bij het beantwoorden van vragen.

**Waarom documenten uploaden?**
- De agent krijgt toegang tot gedetailleerde informatie zonder de instructies te overladen
- Ideaal voor documentatie die te omvangrijk is voor de instructies
- Informatie blijft actueel: werk documenten op elk moment bij zonder de instructies van de agent aan te passen

**Ideaal voor:** productdocumentatie, beleidshandboeken, procesgidsen, trainingsmateriaal, kennisbanken

<Tip>
Gebruik instructies voor kritieke informatie die bij elk antwoord nodig is. Gebruik documenten voor uitgebreid referentiemateriaal dat de agent alleen raadpleegt wanneer relevant.
</Tip>

<Accordion title="Technische details: hoe documentopvraging werkt" icon="gear">

Wanneer je documenten uploadt, gebruikt WonkaChat **RAG (Retrieval-Augmented Generation)** om ze doorzoekbaar te maken voor de agent.

**Hoe het werkt:**
1. **Upload**: jij levert de bedrijfsdocumenten aan
2. **Indexering**: documenten worden verwerkt en doorzoekbaar gemaakt
3. **Opvraging**: indien relevant vindt de agent automatisch informatie in de documenten
4. **Generatie**: de agent geeft een antwoord dat is onderbouwd door jouw echte documentatie

**Tips voor documentvoorbereiding:**
- **Gebruik duidelijke titels**: goed gestructureerde secties verbeteren de nauwkeurigheid van opvraging
- **Houd secties gericht**: één onderwerp per sectie
- **Neem context op**: schrijf secties die op zichzelf begrijpelijk zijn (bijv. "Ons Premium-niveau omvat..." in plaats van enkel "Het omvat...")
- **Blijf consistent**: gebruik overal dezelfde terminologie

<Info>
Geüploade documenten blijven binnen jouw WonkaChat-omgeving en zijn alleen toegankelijk voor gebruikers met toestemming om de agent te gebruiken.
</Info>

</Accordion>

## Voorbeelden per use case

<AccordionGroup>
<Accordion title="Klantenserviceagent" icon="headset">
**Benodigde context:** productfuncties, supportbeleid, probleemoplossingsstappen, communicatierichtlijnen

**Voorbeeld van instructiefragment:**
```
Supportrichtlijnen:
- Verifieer altijd het account voordat je details deelt
- Gebruik kennisbankartikelen voor technische problemen
- Escaleer factuurproblemen boven 500 € naar finance
- Toon van antwoord: empathisch, oplossingsgericht, professioneel
```
</Accordion>

<Accordion title="E-mailassistent" icon="envelope">
**Benodigde context:** stem van het bedrijf, veelvoorkomende e-mailtypes, goedkeuringsworkflows, interne terminologie

**Voorbeeld van instructiefragment:**
```
E-mailstijl:
- Interne e-mails: direct en beknopt
- Externe e-mails: professioneel en beleefd
- Zet relevante belanghebbenden waar nodig in CC
- Gebruik het handtekeningformaat van het bedrijf: [Naam] | [Functie] | [Afdeling]
```
</Accordion>

<Accordion title="Salesassistent" icon="chart-line">
**Benodigde context:** productpositionering, prijzen, doelgroep, salesproces, concurrentie-informatie

**Voorbeeld van instructiefragment:**
```
Salescontext:
- Doelgroep: mid-market bedrijven (50-500 werknemers)
- Belangrijkste waardepropositie: 40% tijdsbesparing op projectbeheer
- Nooit korting geven zonder goedkeuring van een manager
```
</Accordion>
</AccordionGroup>
