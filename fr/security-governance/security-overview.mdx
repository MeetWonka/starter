Cette page explique les protections intégrées à WonkaChat. Pour les certifications, l'hébergement et les régions des modèles, voir [Conformité et gouvernance](/fr/security-governance/compliance-and-governance).

## Connexion et sessions

<AccordionGroup>
<Accordion title="Options de connexion" icon="right-to-bracket">
- **Email et mot de passe.** Les mots de passe sont hachés avec bcrypt et jamais stockés en clair.
- **Authentification unique (SSO).** Les administrateurs peuvent connecter votre fournisseur d'identité via OpenID Connect (Microsoft, Google ou un fournisseur personnalisé) ou SAML.
- **Exiger le SSO pour les utilisateurs non administrateurs.** Une fois le SSO activé, les administrateurs peuvent imposer la connexion via SSO à tous, sauf aux administrateurs de l'organisation.

Configuration : [SSO et 2FA](/fr/administration/sso-and-2fa).
</Accordion>

<Accordion title="Authentification à deux facteurs (2FA)" icon="mobile-screen">
Chaque utilisateur peut activer l'authentification à deux facteurs dans **Paramètres → Compte → Authentification à deux facteurs (2FA)**. La connexion demande ensuite un code généré par votre application d'authentification.
</Accordion>

<Accordion title="Jetons de session" icon="key">
WonkaChat utilise des jetons d'accès de courte durée (15 minutes) et des jetons de rafraîchissement (7 jours). Passé 7 jours sans rafraîchissement, vous devez vous reconnecter.
</Accordion>

<Accordion title="Limitation de débit" icon="gauge">
La connexion, l'inscription, la réinitialisation de mot de passe et les appels API sont limités en débit pour ralentir les attaques par force brute et les abus.
</Accordion>
</AccordionGroup>

## Vos données

<CardGroup cols={2}>
<Card title="Isolées par organisation" icon="building-lock">
Conversations, agents, fichiers, connecteurs et paramètres appartiennent à votre organisation. Les autres organisations ne peuvent pas les voir.
</Card>

<Card title="Chiffrées" icon="lock">
Les données sont chiffrées en transit (TLS 1.2 ou supérieur) et au repos (AES-256).
</Card>

<Card title="Jamais utilisées pour l'entraînement" icon="ban">
Vos données ne servent pas à entraîner des modèles d'IA publics.
</Card>

<Card title="Hébergées en UE" icon="server">
WonkaChat tourne par défaut sur Microsoft Azure West Europe.
</Card>
</CardGroup>

## Comment les modèles d'IA sont sollicités

Quand vous envoyez un message, WonkaChat le transmet au modèle choisi via une passerelle IA (AI gateway). Cette passerelle se connecte à des fournisseurs de modèles comme Microsoft Azure, Google Vertex AI, Mistral et d'autres.

Chaque modèle s'exécute dans une région précise : l'UE, les États-Unis, ou un point d'accès global. **Les données que vous envoyez à un modèle sont traitées dans la région de ce modèle.** Le sélecteur de modèle affiche un badge de région à côté de chaque modèle. Voir [Régions des modèles](/fr/security-governance/compliance-and-governance#regions-des-modeles).

## Connecteurs

Les connecteurs (MCP) permettent aux agents de lire et d'agir dans vos outils : email, fichiers, CRM, etc.

<AccordionGroup>
<Accordion title="Vos permissions, jamais plus" icon="user-lock">
Un connecteur agit avec **votre** compte dans l'outil connecté. Si vous ne pouvez pas voir ou faire quelque chose vous-même dans cet outil, l'agent ne le peut pas non plus.
</Accordion>

<Accordion title="Identifiants personnels" icon="id-card">
Quand vous connectez un outil, la connexion est enregistrée uniquement pour votre compte. Les autres utilisateurs de votre organisation ne peuvent pas utiliser vos identifiants.
</Accordion>

<Accordion title="Connecteurs personnalisés" icon="plug">
Si votre organisation l'autorise, les utilisateurs peuvent ajouter des connecteurs personnalisés dans **Personnaliser → Connecteurs**. WonkaChat les signale : *les connecteurs personnalisés ne sont pas vérifiés par Wonka AI.* N'ajoutez que des serveurs auxquels vous faites confiance.
</Accordion>

<Accordion title="Contrôle administrateur" icon="sliders">
Les administrateurs décident quels utilisateurs et groupes peuvent utiliser chaque connecteur, dans **Paramètres → Organisation → Accès aux connecteurs**. Voir [Groupes et politiques d'outils](/fr/administration/groups-and-tool-policies).
</Accordion>
</AccordionGroup>

<Warning>
Un connecteur peut faire tout ce que ses actions autorisent avec votre compte, y compris envoyer des emails ou supprimer des fichiers. Dans le constructeur d'agent, désactivez les actions dont un agent n'a pas besoin, ou basculez le connecteur en **lecture seule**. Voir [Contrôle d'accès](/fr/security-governance/access-control#restriction-des-outils).
</Warning>
