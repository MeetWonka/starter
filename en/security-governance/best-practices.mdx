WonkaChat is secure by design: your data is encrypted, isolated between organizations, and never used to train public models. These habits help you use it well day to day.

## Scope your requests

<Tabs>
<Tab title="Good tasks" icon="circle-check">
- Analyze this dataset and identify trends
- Draft a reply to this customer inquiry
- Review this document for clarity and errors
- Summarize the key points from this meeting

Specific tasks get better results and are easier to check.
</Tab>
<Tab title="Tasks needing extra care" icon="triangle-exclamation">
- Sending communications on your behalf
- Changes to production data or systems
- Deleting files or records
- Anything you can't easily undo

Review the output carefully, or break the task into smaller reviewable steps.
</Tab>
</Tabs>

## Think before executing

The main everyday risk isn't a security flaw — it's an agent doing something you didn't mean to authorize.

<AccordionGroup>
<Accordion title="Actions that are hard to undo" icon="ban">
- Sending emails or messages to customers
- Deleting files, records or accounts
- Deploying or changing production configuration
- Overwriting a shared document
</Accordion>

<Accordion title="Actions you can safely let an agent do" icon="circle-check">
- Drafting content for you to review
- Analyzing data and summarizing findings
- Searching and retrieving information
- Generating documentation or test data
</Accordion>
</AccordionGroup>

### Reduce risk for sensitive agents

<AccordionGroup>
<Accordion title="Turn off actions the agent doesn't need" icon="lock">
In the agent builder, only enable the connector actions the task requires — for example, keep "draft email" but leave out "send email". See [tool restriction](/en/security-governance/access-control#restricting-what-an-agents-tools-can-do).
</Accordion>

<Accordion title="Test with real data carefully" icon="flask">
Try a new agent on a small, low-stakes case before relying on it for something important. Use anonymized or test data when you can.
</Accordion>

<Accordion title="Break large tasks into steps" icon="list-check">
For multi-step work, review the result of each step before moving to the next, rather than asking for everything at once.
</Accordion>

<Accordion title="Review connector access" icon="eye">
Before connecting an agent to a tool, check what that connector can see and do. Remember it acts with your own permissions in that tool.
</Accordion>
</AccordionGroup>

<Tip>
Combine these habits for higher-stakes work: restrict the agent's tools **and** review its output before anything goes out.
</Tip>

## Common-sense guidelines

<AccordionGroup>
<Accordion title="Review before it has impact">
Treat AI output like a colleague's draft: check it before it reaches customers or production systems.
</Accordion>

<Accordion title="Keep using version control">
For code, commit AI-assisted changes separately so you can track and revert them if needed.
</Accordion>

<Accordion title="Don't ask for illegal or harmful content">
This is about professional ethics and your organization's reputation, not a platform limitation.
</Accordion>

<Accordion title="Verify what matters">
For important decisions, check AI-generated information against authoritative sources. Use AI to speed up research and drafting, not to replace judgment.
</Accordion>
</AccordionGroup>

## Quick reference

| Factor | Lower risk | Higher risk |
|--------|-----------|-------------|
| Reversibility | Drafts, analysis, suggestions | Sent messages, deletions, production changes |
| Scope | Personal work, test data | Customer-facing, organization-wide |
| Review | You check the result before it's used | Executed directly with no review |

<Check>
For higher-risk tasks: [restrict the agent's tools](/en/security-governance/access-control#restricting-what-an-agents-tools-can-do), share narrowly first, and review output before anything ships.
</Check>

## The bottom line

1. **Think before executing** — review before sending, deleting or deploying.
2. **Scope requests clearly** — specific tasks are easier to check.
3. **Use good judgment** — verify what matters, and treat AI as a fast collaborator, not a replacement for it.
